# Documentation development

The published site is Jekyll 3.10 with Just the Docs pinned to v0.10.1. The plugin build does not build this website.

## Build and review

Install Ruby, Bundler, and Node 20 or later, then run from the repository root:

```sh
bundle install
npm ci
npm run changelog:page
npm run docs:build
npm run docs:test
```

`docs:build` writes `.docs-site/`, which is ignored. Serve that output beneath the configured base path, `/hwinfo-streamdeck/`, rather than at a domain root. To test another base path, pass Jekyll's `--baseurl` and `--destination` options. A preview build also needs the preview configuration generated by the publisher.

```sh
node scripts/docs-crawl.mjs http://127.0.0.1:4173/hwinfo-streamdeck/ --manifest scripts/docs-route-contract.json
DOCS_TEST_URL=http://127.0.0.1:4173/hwinfo-streamdeck/ CHROME_PATH=/path/to/chrome npm run docs:test:browser
node scripts/docs-site-shots.mjs /tmp/docs-shots http://127.0.0.1:4173/hwinfo-streamdeck/ reviewed-commit
```

Set the environment variables with the syntax appropriate to your shell. The browser tests report UNAVAILABLE when no site URL is supplied. Screenshot tooling discovers Chrome on Windows, macOS, or Linux; `CHROME_PATH` overrides the executable. `DOCS_SHOTS_VIEWPORTS=360x800,768x1024,1440x900,2560x1440` supplies additional viewports. Each screenshot run records the real browser version, errors, failed requests, full-page dimensions, URL and supplied source identity. Certificate exceptions are not part of the workflow.

The route contract records the 16 original routes and 192 article fragments from the Jekyll build of `bb4aedecbce499e199df8af63793a1490c0fb6ed`. Preserve those destinations or add an explicit alias when changing a heading. Crawler tests check actual HTML, links, responsive images, the search index, and private-path 404s. Browser tests cover search input and paste, queries entered before the index loads, disclosure deep links, mobile navigation, and native-modal keyboard behavior.

## Preview publication

The authorized preview is the existing public `slawrensen/hwinfo-streamdeck-preview` repository. Its `main` branch is published by GitHub Pages. It inherits `docs.slawrensen.com` from the account site and deliberately has no `CNAME`.

1. Inspect source and preview branch heads and open PRs. Work on an isolated documentation branch.
2. Review and commit the documentation. The publisher ignores uncommitted and untracked files.
3. Record the preview branch's current full SHA immediately before publication.
4. Stage and inspect the committed files:

```sh
node scripts/docs-preview-publish.mjs --stage-only --expected-head FULL_PREVIEW_SHA
```

5. Build the generated stage with Jekyll and crawl its `/hwinfo-streamdeck-preview/` base path with `--preview --build-id docs-SOURCE_SHA_PREFIX`. Test browser journeys against both base paths.
6. Publish with authenticated Git and GitHub CLI:

```sh
node scripts/docs-preview-publish.mjs --publish --expected-head FULL_PREVIEW_SHA
```

The publisher keeps the prior preview commit as a parent and uses an explicit expected-head lease. If the branch moves, inspect and reconcile before retrying. Authentication or network failures are errors, never reasons to create a replacement repository or change visibility. An equivalent GitHub API transport must create the same staged blobs/tree, retain the prior commit parent, and update the ref with the same expected SHA.

7. Wait for the Pages deployment associated with the generated preview commit. Verify the served `docs-build.json`, HTML `docs-build-id`/`docs-source-sha` metadata, `noindex`, preview marker, and asset bytes against that committed stage. A push alone is not deployment verification.
8. Open a reviewable source PR and record the source commit, previous and generated preview commits, deployment run, checks and limitations. Production promotion is a separate decision.

`docs/release/` and this README are excluded. No private release documents should be added merely to make a documentation check pass. `docs/changelog.md` remains generated from `CHANGELOG.md`; change its wrapper through `scripts/gen-changelog-page.mjs` and regenerate it.

## Shared frontend and assets

`_data/navigation.yml` groups existing routes without creating replacement URLs. `_layouts/default.html` and `_includes/components/` provide the shell. `assets/css/docs.css` contains shared tokens and responsive styles; `assets/js/docs.js` adds table/code scroll regions, contents, disclosure reveal, and the native image dialog. Basic navigation, articles and full-image links remain usable without JavaScript.

`assets/js/just-the-docs.js` is the upstream v0.10.1 script with a small documented patch for input/paste, queries entered before search data arrives, and preserving scroll position during search. Its MIT license is adjacent. Recheck these differences when upgrading the pinned theme.

Use genuine captures or production-renderer output. Optimized showcase derivatives retain source hashes, crop coordinates and release provenance in `assets/img/showcase/provenance.json`. Preserve masters, distinguish samples/app captures/hardware photographs, retain credits, and add intrinsic dimensions. Do not describe a shared touch-strip picture as a graph spanning multiple dials.

### Prose and display gallery

The shared prose cap is `48rem` (768px at the default root size), with 19px desktop body text and the existing 16px phone text. Tables keep their wider space and share the prose's left edge. The choice was checked against 97 paragraphs across Sensor Dial, Sensor Reading, Troubleshooting and Data sources at 1440px and 1920px. Complete lines had a median of 87 characters and a 90th percentile of 92, compared with 86 and 91 at the former roughly 681px / 17px setting. The proposed 832px / 17px setting produced 106 and 112. These are Chromium measurements using its available Liberation Sans fallback; other system fonts can wrap differently. Phone paragraph dimensions and wrapping were unchanged at 320px and 390px.

The measure follows the distinction between prose and wider reference content in [GOV.UK layout guidance](https://design-system.service.gov.uk/styles/layout/) and [USWDS typography guidance](https://designsystem.digital.gov/components/typography/). It is a measured choice for these reference pages, not a claim of universal optimal line length or full accessibility conformance.

The homepage gallery uses five maintainer-supplied app captures. `node scripts/docs-gallery-images.mjs` reproduces native 830 × 450 PNG and lossless WebP crops from the retained masters and checks decoded pixel equality. `assets/img/showcase/gallery/provenance.json` records hashes, crop coordinates, matching key and touch-strip geometry, and the limits of background-image provenance. Do not offer those composited screenshots as clean background downloads.

Gallery arrows and Expand stay below the image; nothing overlays the capture. The native dialog keeps navigation outside the image stage, offers Fit and Actual size, and reserves arrow keys for panning at Actual size. Group links use `data-image-group`; source attribution can use `data-image-credit`, `data-image-credit-url`, `data-image-license` and `data-image-license-url`. Credit is shown separately from the shortened image description. Normal full-image links and all gallery slides remain available without JavaScript.

Documentation validation does not qualify a plugin release. Windows/HWiNFO installation, physical-device checks, signing, private release-runbook gates and fresh manual VirusTotal validation remain separate.
